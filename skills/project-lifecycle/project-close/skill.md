# Project Close - Project Closing Orchestrator

## Purpose

Manages the entire project closing workflow as a single pipeline.
Executes 5 phases in sequence: pre-close check, deliverables package, client guide, repository cleanup, and closing report.
Automatically detects project state, collects missing info via interview, and generates all closing artifacts including a branded HTML presentation.

## Usage

```
/project-close              # Check current progress + guide to next step
/project-close status       # Full pipeline status dashboard (auto-detected)
/project-close start        # Start sequentially from Phase 1
/project-close resume       # Resume from where it was interrupted
/project-close from guide   # Start from a specific Phase
/project-close pre-check    # Run Phase 1 only
/project-close deliverables # Run Phase 2 only
/project-close guide        # Run Phase 3 only
/project-close repo-cleanup # Run Phase 4 only
/project-close report       # Run Phase 5 only
```

## Auto-Detection Logic

Before starting any interview, scan the project to auto-populate as much information as possible.

### Detection Sources

| Source | What to Extract |
|--------|----------------|
| `package.json` (backend, frontend, frontend-dashboard) | Project name, version, tech stack, dependencies, scripts |
| `.env` / `.env.example` | External services (AWS S3, Redis, PostgreSQL, Firebase, SMTP, etc.) |
| `docker-compose.yml` | Infrastructure components, port mappings, volumes |
| `ecosystem.config.js` / `pm2-start.js` | PM2 process configuration |
| `store-prep/pipeline-status.json` | App name, store submission status |
| `store-prep/app-info.md` | Client-facing app information |
| `CLAUDE.md` / `PROJECT_OVERVIEW.md` | Architecture, feature summary |
| `change-request-log.md` | Change request history |
| `git log` | First/last commit dates, total commits, contributors, branches, tags |
| `git remote -v` | Repository URL |
| `gh pr list --state open` | Open pull requests |
| `gh issue list --state open` | Open issues (if GitHub Issues used) |
| `.claude_eddy/client-closing-guide.md` | Existing client guide template |

### Detection Execution

Run these checks at pipeline start and cache results in `close-status.json`:

```
# Project basics
Read: backend/package.json → name, version, dependencies
Read: frontend/package.json → name, version, dependencies
Read: frontend-dashboard/package.json → name, version, dependencies

# External services
Read: backend/.env.example → list all service-related variables
Grep: AWS|S3|FIREBASE|REDIS|SMTP|TOSS|KAKAO|NAVER|ZOOM in .env.example

# Infrastructure
Glob: docker-compose*.yml → Docker services
Glob: ecosystem.config.* → PM2 config
Glob: nginx*.conf → Nginx config

# Store status
Read: store-prep/pipeline-status.json → store submission state
Read: store-prep/app-info.md → app metadata

# Git analysis
Bash: git log --reverse --format="%ai" | head -1 → first commit date
Bash: git log -1 --format="%ai" → last commit date
Bash: git shortlog -sn --no-merges → contributor stats
Bash: git rev-list --count HEAD → total commits
Bash: git branch -r → remote branches
Bash: git tag -l → tags
Bash: git branch --merged main → merged branches

# Open items
Bash: gh pr list --state open --json number,title,author 2>/dev/null
Bash: gh issue list --state open --json number,title 2>/dev/null
```

## Phase 1: Pre-Close Check

### Purpose
Verify the project is ready for closing. Surface any blockers before proceeding.

### Auto-Detection Scans

1. **Unmerged branches**: `git branch -r --no-merged main`
2. **Open PRs**: `gh pr list --state open`
3. **Open issues**: `gh issue list --state open`
4. **Store status**: Read `store-prep/pipeline-status.json`
5. **Type-check**: `npm run type-check` in backend (report pass/fail, don't block)
6. **Build check**: `npm run build` in frontend/frontend-dashboard (report pass/fail)

### Interview (All questions upfront)

> **Key Rule**: Collect ALL information needed for the entire pipeline in Phase 1.
> Phases 2~5 execute automatically with no further questions.
> Use AskUserQuestion with maximum grouping (2~3 rounds max).

**Round 1 — Project & Meeting:**

1. **Project name** — auto-fill from package.json / store-prep. Ask only if not detected
2. **Client name** — "Client name with title? (e.g., 김철수 대표님)"
3. **Closing meeting date** — "When is the closing meeting scheduled? (e.g., 2026-04-15)"
4. **Payment status** — "What is the current payment status?"
   - Options: Fully paid / Balance remaining / Not yet invoiced
5. **Client QA sign-off** — "Has the client signed off on all features?"
   - Options: Yes / No / Pending

> **Auto-detected (no question needed):**
> - Project duration: from git first commit ~ last commit
> - Outstanding issues: from `gh pr list --state open` and `gh issue list --state open`

**Round 2 — Delivery & Maintenance:**

6. **Code delivery method** — "How should the source code be delivered?"
   - Options: GitHub repository access / ZIP archive / Both
7. **Production server** — "What is the production server provider?"
   - Options: AWS EC2 / Cafe24 / Docker on VPS / Other (specify)
8. **Warranty period** — "Agreed free maintenance period?"
   - Options: 1 month / 2 months / 3 months (Recommended) / Custom
9. **PM contact** — "PM contact info for client documents? (email + phone)"
   - Used in: maintenance-guide, closing-presentation Thank You slide
10. **Total effort** — "Estimated total effort? (e.g., 4 months, 1 developer)"
11. **Lessons learned** — "Any key takeaways from this project?" (free text, optional — for internal report only)

> **Removed from interview (use sensible defaults):**
> - Maintenance owner: default TBD
> - Code cleanup: default Skip (can be done before code delivery)
> - Release tag: default v[package.json version] or v1.0.0
> - Archive repository: default No (keep active during maintenance)
> - Branch cleanup: auto-detect merged branches, skip if none

| 앱 출시 현황 | store 카드 동일 너비, 상태 뱃지 색상 |
| 서비스 유지 안내 | info-card 텍스트 수용, 줄간격 |
| 외부 서비스 관리 | renewal-table 컬럼 정렬, 글자 잘림 없음 |
| 자가진단 안내 | checklist 항목 가독성 |
| 향후 일정 | timeline 항목 정렬, 라벨/텍스트 수용 |
| Q&A | 중앙 정렬, 오버플로 없음 |
| Thank You | 중앙 정렬, 저작권 하단 잘림 없음 |

**5.4 Fix Issues**

- **Structural** (CSS/layout) → Fix in the HTML AND propagate to `~/.claude/skills/project-close/skill.md` Phase 5 CSS block (structural fixes only: font-size, padding, grid, gap, max-width)
- **Content-specific** → Fix in HTML only (do not propagate)

**5.5 Re-Verify**

Re-inspect after fixes. Max **3 iterations**. Remaining issues → report in Phase 5 output, don't block.

**5.6 Close Browser**

Close Playwright session.

**5.7 QA Report**

Include in Phase 5 completion message:
```
QA (Playwright, 1920×1080):
- Slides inspected: N
- Issues found: M
- Auto-fixed: K
- Propagated to skill.md: J
- Remaining: M - K
```

**Error handling**:
- Playwright MCP unavailable → skip QA, warn in Phase 5 message
- Iteration limit reached → report remaining issues, continue
- Mid-run failure → close browser, partial report, do not block Phase 5

## Execution Algorithm

### `/project-close` or `/project-close status`

1. Run auto-detection (file system + git + package.json + .env)
2. Read `close-status.json` (if absent, show "Pipeline not started" and suggest `/project-close start`)
3. Sync auto-detection results with JSON state
4. Calculate overall progress (phases completed / total phases * 100)
5. Output dashboard
6. Guide to next available Phase

### `/project-close start`

1. Run pre-flight (gitignore check)
2. Run auto-detection
3. Initialize `close-status.json`
4. Execute Phase 1 (Pre-Close Check)
5. If PASS → proceed to Phase 2+3 (can be parallel)
6. If FAIL → report blockers, ask whether to proceed anyway

### `/project-close resume`

1. Run auto-detection
2. Read `close-status.json`
3. Find first `pending` phase
4. Execute that phase

### `/project-close from <phase>`

1. Validate that earlier phases are complete (warn if not, but allow override)
2. Execute the specified phase

### `/project-close <phase-name>`

1. Execute only the specified phase (pre-check, deliverables, guide, repo-cleanup, report)
2. Update `close-status.json` for that phase only

## PDF Generation (for-client/ documents)

After generating `for-client/` markdown files, convert them to branded PDF for client delivery.

### Process

1. **Generate branded HTML** for each `for-client/*.md` document
   - Use Potential Inc branding: `#624DFF` accent, `#050042` headings, Inter font
   - A4 page layout with header (Potential logo + document date), proper margins
   - Tables with `#f8f7ff` header background, `#e8e6f0` borders
   - Section numbers in accent color, section-note boxes with left border
   - Footer: "Copyright [YEAR]. Potential INC. All rights reserved"
2. **Convert HTML → PDF** using Puppeteer
   - Use Puppeteer from md-to-pdf global install: `require(path.join(process.env.APPDATA, 'npm/node_modules/md-to-pdf/node_modules/puppeteer'))`
   - If Puppeteer not available: `npm install -g md-to-pdf` first
   - Settings: format A4, printBackground true, zero margins (margins handled in HTML)
3. **Output**: `for-client/*.pdf` alongside the `.md` and `.html` source files

### Documents to convert

PDF file names follow the `--lang` flag:

**`--lang ko` (default):**

| Source | Output |
|--------|--------|
| `maintenance-guide.md` | `서비스 유지 가이드.pdf` |
| `external-services.md` | `외부 서비스 관리 현황.pdf` |
| `sign-off.md` | `검수확인서.pdf` |

**`--lang en`:**

| Source | Output |
|--------|--------|
| `maintenance-guide.md` | `Maintenance Guide.pdf` |
| `external-services.md` | `External Services.pdf` |
| `sign-off.md` | `Sign-off.pdf` |

> `closing-presentation.html` stays as HTML (browser-based slideshow, not suitable for PDF).
> The `.html` intermediate files are kept alongside PDFs for future regeneration.

## Error Handling

| Scenario | Action |
|----------|--------|
| No `package.json` found | Ask for project name manually, skip dependency detection |
| No `.env.example` found | Warn, ask user to list external services manually |
| No `store-prep/` directory | Skip store status, note "Store submission not applicable" |
| No `change-request-log.md` | Skip change request section in report |
| `code-cleanup` not available | Skip automated cleanup, manual only |
| No git remote | Warn, ask user for repo URL |
| Repository already archived | Skip archival step, note in log |
| No `gh` CLI available | Skip PR/issue checks, note limitation |
| `close-status.json` corrupted | Re-initialize from auto-detection |
| Phase run out of order | Warn but allow (user may have valid reason) |
| Client info in `store-prep/app-info.md` | Reuse without re-asking |
| Interview interrupted | Save partial state to `close-status.json`, resume with `/project-close resume` |
